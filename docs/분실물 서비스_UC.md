# 분실물 서비스 Use Case Description

## 1. 작성 기준

본 문서는 [UC_v0.2.md](UC_v0.2.md)의 서비스 단위 Use Case를 상세화한다. `[논의]`는 고객 또는 운영 책임자의 결정이 필요한 사항이며, 명시되지 않은 내용을 확정하지 않는다.

## 2. UC_01 — 분실물 조회 및 문의 안내

| 항목 | 내용 |
|---|---|
| ID / 이름 | UC_01 / 분실물 조회 및 문의 안내 |
| 범위 상태 / 우선순위 | 포함 / 높음 |
| 사용자와 목표 | **분실 학생**이 분실물의 보관 여부·보관 위치·공식 문의 방법을 확인하여, 불필요한 행정실 방문을 줄이고 필요한 경우 적절한 담당 부서에 문의한다. |
| 관련 고객 요구, 정책 ID | NEEDS_1, NEEDS_4, NEEDS_6 / Pol_00, Pol_01, Pol_02 |
| 관련 SRS ID | FR_00, FR_01, FR_06, NFR_00 |
| 사전조건 | 조회에 사용할 분실물 정보가 시스템에 하나 이상 등록되어 있다. 공개 가능한 정보 항목이 정책에 따라 설정되어 있다. |
| 시작 사건 | 분실 학생이 앱 또는 서비스에서 분실물 조회를 시작한다. |
| 기본 흐름 | 1. 분실 학생이 검색 조건을 입력한다.<br>2. 시스템이 조건에 맞는 등록 물품을 조회한다.<br>3. 시스템이 물품의 보관 상태와 공개 가능한 보관 위치를 표시한다.<br>4. 시스템이 공식 담당 부서와 문의 방법을 표시한다.<br>5. 분실 학생이 결과를 확인하고 Use Case를 종료한다. |
| 대안, 예외 흐름 | **A1 — 검색 결과 없음:** 2단계 → 조건에 맞는 물품이 없음 → 시스템이 ‘조회 결과 없음’을 안내 → 분실 학생은 검색 조건을 바꿔 1단계로 복귀하거나 종료한다.<br><br>**A2 — 인도 완료 물품 조회:** 3단계 → 물품 상태가 인도 완료임 → 시스템이 상태를 표시 → [논의] 인도 완료 물품의 보관 위치도 표시할지 결정 필요 → 결과 확인 후 종료한다.<br><br>**A3 — 보관 위치 비공개:** 3단계 → 위치가 공개 범위에 포함되지 않음 → 시스템이 위치 대신 공식 문의 방법을 안내 → 4단계로 진행한다.<br><br>**A4 — 문의 정보 미설정:** 4단계 → 담당 부서 또는 문의 방법이 설정되지 않음 → [논의] 운영 담당자에게 설정을 요청하는 안내 문구와 대체 연락 방법을 정해야 함 → 종료한다. |
| 사후조건 — 성공 | 조회 이력의 저장 여부와 관계없이, 분실 학생에게 정책상 공개 가능한 보관 상태·위치·문의 정보가 표시된다. |
| 사후조건 — 실패 / 취소 | 결과가 없거나 조회를 취소한 경우 물품 정보는 변경되지 않는다. [논의] 검색어·조회 이력을 저장할지와 보존 기간은 정해야 한다. |
| 미확정 사항, 고객 질문 | [논의] 검색 조건은 무엇인가? (물품명, 습득일, 물품 종류, 보관 장소 등)<br>[논의] 인도 완료 물품과 보관 위치의 공개 범위는 어디까지인가?<br>[논의] 보관 위치는 행정실·담당 부서·상세 보관함 중 어느 수준까지 표시하는가?<br>[논의] 공식 문의 정보의 필수 항목은 무엇인가? |

## 3. UC_02 — 습득물 등록

| 항목 | 내용 |
|---|---|
| ID / 이름 | UC_02 / 습득물 등록 |
| 범위 상태 / 우선순위 | 확정 / 높음 |
| 사용자와 목표 | **습득 학생**이 습득한 물품을 앱에서 즉시 등록하여 물품이 주인에게 돌아갈 가능성을 높인다. **행정 담당자**는 분실물 센터로 접수된 습득 물품을 등록하여 관리 대상에 포함한다. |
| 관련 고객 요구, 정책 ID | NEEDS_2, 확정 사항(습득 학생 앱 직접 등록; 고객 요구 ID 없음) / Pol_03, Pol_07, Pol_08 |
| 관련 SRS ID | FR_02, FR_07, NFR_01 |
| 사전조건 | 습득 학생 또는 행정 담당자가 등록 화면에 접근할 수 있다. 실제 개인정보가 아닌 가상 데이터만 사용한다. [논의] 역할별 접근 제어 및 학교 인증 연동 여부는 현재 범위에서 제외되어 있다. |
| 시작 사건 | 습득 학생이 앱에서 습득물 등록을 선택하거나, 행정 담당자가 분실물 센터에 접수된 물품의 등록을 시작한다. |
| 기본 흐름 | 1. 사용자가 등록 경로(습득 학생 앱 직접 등록 또는 행정 담당자 센터 접수 등록)를 선택한다.<br>2. 사용자가 습득 물품 정보를 입력한다.<br>3. 시스템이 필수 입력 항목을 검증한다.<br>4. 시스템이 물품 정보를 저장하고 등록 결과를 안내한다.<br>5. 등록된 물품은 이후 물품 관리 대상이 된다. |
| 대안, 예외 흐름 | **A1 — 필수 정보 누락 또는 형식 오류:** 3단계 → 필수 항목 누락 또는 형식 오류 → 시스템이 오류 항목을 표시 → 2단계로 복귀한다.<br><br>**A2 — 등록 취소:** 2단계 또는 3단계 → 사용자가 취소를 선택 → 입력 중인 내용을 폐기하거나 임시 저장 → [논의] 임시 저장 제공 여부·보존 기간을 정해야 함 → 종료한다.<br><br>**A3 — 습득 학생 직접 등록 건의 공개 처리:** 4단계 → 습득 학생이 등록한 건임 → [논의] 즉시 조회에 공개할지, 행정 담당자의 확인·승인 후 공개할지 결정 필요 → 결정된 정책에 따라 공개 또는 검토 대기 상태로 종료한다.<br><br>**A4 — 유사 물품 중복 등록 가능성:** 3단계 → 유사한 기존 등록 정보가 발견됨 → [논의] 중복 경고만 제공할지, 등록을 제한할지, 행정 담당자 검토로 보낼지 결정 필요 → 사용자가 수정·계속 등록·취소 중 선택한다. |
| 사후조건 — 성공 | 물품 정보가 등록되며, 등록 경로와 등록 시점이 관리 가능한 상태로 보존된다. [논의] 등록자 식별 정보의 저장 여부는 개인정보 정책에 따라 결정해야 한다. |
| 사후조건 — 실패 / 취소 | 검증 실패 또는 취소 시 물품 정보는 정식 등록되지 않는다. 임시 입력값의 저장 여부와 보존 기간은 [논의] 사항이다. |
| 미확정 사항, 고객 질문 | [논의] 두 등록 경로의 공통·개별 필수 입력 항목은 무엇인가?<br>[논의] 습득 학생이 직접 등록한 물품은 누가, 어떤 기준으로 확인·승인하는가?<br>[논의] 등록 후 수정·삭제 권한은 누구에게 부여하는가?<br>[논의] 중복 등록 판단 기준과 대응 방식은 무엇인가? |

## 4. UC_03 — 분실물 센터 물품 관리

| 항목 | 내용 |
|---|---|
| ID / 이름 | UC_03 / 분실물 센터 물품 관리 |
| 범위 상태 / 우선순위 | 포함 / 높음 |
| 사용자와 목표 | **행정 담당자**가 등록된 물품 정보를 최신으로 관리하고 보관 중/인도 완료 상태를 구분하여, 실제 분실물 센터의 보관 현황과 서비스 정보를 일치시키려 한다. |
| 관련 고객 요구, 정책 ID | NEEDS_2, NEEDS_3 / Pol_07 |
| 관련 SRS ID | FR_03, FR_04, FR_05 |
| 사전조건 | 관리할 물품 정보가 등록되어 있다. 행정 담당자가 물품 관리 기능을 사용할 수 있다. [논의] 역할별 권한의 구체적인 범위는 미정이다. |
| 시작 사건 | 행정 담당자가 등록 물품의 정보 수정, 보관 상태 변경 또는 인도 완료 처리를 시작한다. |
| 기본 흐름 | 1. 행정 담당자가 관리할 물품을 선택한다.<br>2. 시스템이 현재 물품 정보와 상태를 표시한다.<br>3. 행정 담당자가 정보 또는 상태를 변경한다.<br>4. 시스템이 입력값과 상태 변경 조건을 검증한다.<br>5. 시스템이 변경 내용을 저장하고 최신 상태를 표시한다.<br>6. 이후 분실 학생 조회 시 변경된 상태가 구분되어 표시된다. |
| 대안, 예외 흐름 | **A1 — 관리 대상 없음:** 1단계 → 선택한 물품이 없거나 존재하지 않음 → 시스템이 안내 메시지를 표시 → 물품 목록 선택 단계로 복귀하거나 종료한다.<br><br>**A2 — 인도 완료 처리:** 3단계 → 행정 담당자가 인도 완료로 변경 → 시스템이 상태를 인도 완료로 저장 → 5단계로 진행한다.<br><br>**A3 — 인도 완료 오처리 정정:** 3단계 → 이미 인도 완료인 물품의 정정이 필요함 → [논의] 정정 권한, 승인 여부, 변경 사유 기록 여부를 결정해야 함 → 결정된 절차에 따라 상태를 변경하거나 종료한다.<br><br>**A4 — 권한 없음:** 3단계 → 담당자에게 수정 또는 상태 변경 권한이 없음 → 시스템이 권한 부족을 알림 → 변경 없이 종료한다.<br><br>**A5 — 저장 실패:** 5단계 → 시스템 저장에 실패 → 시스템이 실패 사실과 재시도 방법을 알림 → [논의] 입력값의 임시 보존 여부를 정해야 함 → 재시도 또는 종료한다. |
| 사후조건 — 성공 | 변경된 물품 정보와 보관·인도 상태가 저장되고, 조회 화면에서 최신 상태로 구분되어 표시된다. |
| 사후조건 — 실패 / 취소 | 저장 실패 또는 취소 시 기존에 저장된 물품 정보와 상태가 유지된다. [논의] 변경 시도·오류·정정 이력의 저장 범위와 보존 기간은 정해야 한다. |
| 미확정 사항, 고객 질문 | [논의] 정보 수정·삭제와 상태 변경을 할 수 있는 역할은 누구인가?<br>[논의] 인도 완료의 판단 기준 및 증빙 필요 여부는 무엇인가?<br>[논의] 상태 정정에 승인, 변경 사유, 이력 보관이 필요한가?<br>[논의] 저장 실패 시 재시도와 임시 보존을 어떻게 처리할 것인가? |

| 사후조건 — 실패 / 취소 | 안내가 없거나 사용자가 취소해도 물품 등록·물품 상태에는 변경이 없다. |

## 6. 공통 보존·개인정보 제약

| 항목 | 내용 |
|---|---|
| 데이터 범위 | 실제 개인정보가 아닌 가상 데이터만 사용한다. |
